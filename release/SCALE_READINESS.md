# MORROW 10만+ 운영 준비 기준

이 문서는 MVP 체크리스트가 아니라, 실제 회원 10만 명 이상을 수용하기 위한 운영 기준과 출시 게이트다. 현재 배포는 기능·보안 가드레일을 갖춘 단일 Coders.kr 프로젝트이며, 아래 부하·복구 검증을 통과한 뒤 트래픽을 단계적으로 늘린다.

## 목표와 SLO

- 월간 활성 회원 100,000명, 피크 동시 접속 5,000명, 피크 API 250 RPS를 초기 용량 목표로 둔다.
- 인증·추천·매치·메시지 쓰기 요청의 가용성 99.9%, p95 500ms 이하(사진 업로드 제외)를 추적한다.
- WebSocket 연결은 노드별 한도를 정하고 Redis pub/sub를 통해 노드 간 이벤트를 전달한다. 노드 증설 시 세션을 특정 인스턴스에 고정하지 않는다.
- 모든 시간은 UTC `TIMESTAMPTZ`로 저장하고 화면에서만 한국 시간으로 표시한다.

## 코드에 반영된 확장성 가드레일

- `V15__scale_hot_path_indexes.sql`: 메시지 최신 미리보기·읽지 않은 수·알림·약속·신고 큐의 복합/부분 인덱스.
- 매치 목록은 최신 메시지와 읽지 않은 수를 각각 한 번에 조회해 매치 수만큼 반복되는 N+1 쿼리를 제거했다.
- HTTP와 WebSocket 속도 제한은 Redis 분당 버킷을 우선 사용하고, Redis 장애 시에도 키 공간을 10,000개 이하로 정리하는 프로세스 폴백을 사용한다.
- `/api/health/live`는 프로세스 생존만, `/api/health/ready`는 PostgreSQL과 Redis 연결까지 확인한다. 라우터는 readiness가 아닌 인스턴스로 트래픽을 보내지 않는다.
- 목록 API는 서버 상한(추천 20, 매치 50, 메시지 50)을 유지해 한 요청이 메모리와 DB를 독점하지 않도록 했다.

## 출시 전 단계적 부하 검증

1. **스테이징 데이터**: 실데이터를 복사하지 말고 익명화된 합성 데이터로 사용자 100k, 매치 1m, 메시지 10m 규모를 만든다. 사진 바이트는 오브젝트 스토리지의 테스트 버킷을 사용한다.
2. **시나리오**: (a) 익명 랜딩/로그인 제공자 조회, (b) 로그인 후 추천 필터, (c) 좋아요→매치, (d) 메시지/사진 전송, (e) 약속·안전 확인, (f) WebSocket 재연결과 다중 노드 이벤트를 각각 15분 이상 실행한다.
3. **게이트**: 오류율 < 0.1%, p95 < 500ms, DB 커넥션 풀 고갈 0회, Redis 메모리 eviction 0회, WebSocket 재연결 폭주 없음. 초과하면 용량을 늘리고 원인을 고친 뒤 다시 실행한다.
4. **카오스 확인**: 스테이징에서 Redis를 60초 차단해 HTTP/WS 폴백과 readiness 격리가 작동하는지 확인한다. PostgreSQL 장애 시 쓰기 요청이 중복 생성되지 않고 복구 후 Flyway가 정상 재개되는지 확인한다.
5. **점진 공개**: 내부 1% → 초대 5% → 25% → 100% 순서로 늘리며 각 단계에서 30분 동안 SLO와 신고/차단 지표를 확인한다. 기능 플래그와 즉시 롤백 커밋을 유지한다.

## 운영 관측과 복구

- 구조화 로그에는 `X-Request-ID`, 상태 코드, 지연시간, 사용자 식별자 해시만 남기고 토큰·메시지 본문·사진·이메일은 기록하지 않는다.
- PostgreSQL은 일일 전체 백업 + PITR 로그를 보관하고, 월 1회 별도 환경 복구 리허설을 한다. Redis는 캐시/실시간 전달 계층이므로 재생성 가능하게 운영한다.
- 알림 기준: readiness 2분 연속 실패, 5xx 1% 초과 5분, p95 1초 초과 5분, 신고 대기열 급증, 저장소 80% 초과.
- 장애 시 신규 가입/사진 업로드를 기능 플래그로 먼저 제한하고, 읽기·안전·차단을 우선 유지한다. 복구 후 중복 메시지와 미처리 알림을 점검한다.

## 반복 자가진단

운영 URL에 비파괴 요청만 보내는 짧은 스모크는 다음처럼 실행한다. 인증 토큰을 요구하지 않으며 보호 API가 익명에게 401/403을 반환하는지도 확인한다.

```powershell
pwsh ./release/self-test.ps1 -BaseUrl https://morrow.coders.kr -DurationMinutes 5 -IntervalSeconds 15
```

이 스크립트는 실제 회원 트래픽을 대체하지 않는다. 10만 명 용량 판정은 반드시 별도 스테이징에서 승인된 부하 도구와 합성 계정으로 수행한다.

## 현재 제한과 다음 운영 작업

- 카카오·네이버·구글 OAuth와 카카오맵 키가 운영 환경에 있어야 실제 가입 흐름을 검증할 수 있다. 키가 없으면 제공자 목록은 준비 상태로만 표시한다.
- Coders.kr의 인스턴스 수·DB/Redis 요금제·스토리지 CDN 상한은 계정 설정에 따라 달라진다. 위 RPS 목표를 초과할 조짐이 보이면 먼저 수평 확장과 DB 읽기 분리를 검토한다.
- 실제 앱스토어 출시 전에는 개인정보 영향평가, 신고 대응 SLA, 청소년 유입 차단 정책, 사진/텍스트 자동 모더레이션 공급자를 별도로 승인한다.
